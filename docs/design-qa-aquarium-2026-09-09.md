## 发现并修复

- P1：默认 Canvas 宽度恰为 300 时，原逻辑未初始化高度，导致紧凑版纵向拉伸。改为同时检查宽高。
- P2：旧的固定紧凑/迷你样式与自由尺寸冲突。移除旧尺寸定位，用容器单位与断点适配。
- P2：缩放角与清洁 HUD 的结束按钮重叠。互动期间隐藏缩放角，重新验证结束按钮回到 idle。
- P2：拖动后的点击拦截可能持续到下一次操作。新 pointerdown 清除旧拦截；拖动生成的 click 单次拦截。
- P2：迷你玩法面板挤压。缩小行间距并保持滚动与关闭按钮可用。

本轮已检查的组件范围内无剩余 P0/P1/P2 视觉问题。夜间为栅格灯光加 2.5D 水位，非物理流体/光照模拟。

## 功能验证

- 22 项单元测试通过：原有 18 项额度/互动，加四角固定对角点、最小/最大尺寸、负坐标屏幕移动、较小工作区适配。
- 类型检查、Vite 生产构建与 Electron 编译通过。
- 浏览器操作：从宝箱上拖动触发 move 手势，玩法保持 idle；轻点打开宝箱。
- 擦拭真实拖动达到 38%，结束后回到 idle。工具按钮不启动拖窗。
- 四角中的右下角实际指针拖动到手势结束，fixture 收到 se / moved / ended。
- Ctrl 滚轮将迷你 190 px 改为 201 px，实际 DOM 宽度同步；菜单在迷你尺寸可用。
- 鼠标移出后 header 隐藏，移回后显示；状态截图检查通过。

## 原生与打包边界

原生 Electron 已启动，读取原有登录并显示真实额度；新透明画布与方形窗口正常加载。原生自动化的坐标拖动出现 `windowNotFoundAtPosition` / `noWindowsAvailable`，未将该尝试记为原生拖动通过。浏览器 fixture 验证的是渲染器手势与布局，主进程屏幕计算由纯函数测试覆盖；跨屏拖动、OS 缩放、重启后自定义宽度恢复仍需实际安装交互确认。

v0.3.0 GitHub 工作流打包 Windows x64、Mac arm64 和 Mac x64；CI 构建结果以对应 Actions 运行状态为准。安装包仍为内部未签名预览包。
