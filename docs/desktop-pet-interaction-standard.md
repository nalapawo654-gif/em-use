# 桌宠基础交互规范

版本：1.3 · 2026-09-12

适用范围：EM Use 当前的「额度小鱼缸」「充气牛马」「林间海狸鼠」，以及后续所有新增桌宠。本文统一窗口、账户、操作显隐、反馈与退出等公共行为；每只桌宠独立设计互动种类、名称、手势、道具、动画与完成条件，不要求共享一套动作清单。与旧设计计划冲突时，以本文为准；用户后续明确提出的变更应同步更新本文。

本文基于当前源码整理。“必须”表示新增实现的要求，不代表现有桌宠的所有细节均已通过原生验收。现有差异见第 9 节。

## 1. 常态呈现

- 桌面是背景。使用透明、无边框、无系统阴影的悬浮窗口；宠物、必要的环境物件和额度展示构成主体，不增加常驻的大底板、完整矩形风景背景或网站式说明区。
- 常态不显示顶部操作栏、侧边工具、底部状态操作、登录按钮和缩放手柄。鼠标移入桌宠窗口区域才显示，移出后收起。
- 宠物主体与核心额度保持可见、可感知；隐藏的是常规操作区。角色台词、木牌、小块草地等可按角色设计保留。
- 正在互动的提示、按玩法需要展示的进度、结束按钮，以及持续姿态的恢复按钮属于当前动作反馈，不随常规工具一起隐藏。
- 浏览器预览可以有场景选择、说明、状态样例和互动展示；这些展示区不得带入原生桌宠窗口。

## 2. 操作区显隐

| 条件 | 常规操作区 | 缩放手柄 | 面板 / 当前动作提示 |
| --- | --- | --- | --- |
| 未悬停、无键盘焦点、未打开面板 | 隐藏 | 隐藏 | 有正在进行的动作时保留动作提示 |
| 鼠标悬停 | 显示 | 无面板、无动作提示时显示 | 按各自状态显示 |
| 桌宠内存在键盘可见焦点 | 显示 | 无面板、无动作提示时显示 | 按各自状态显示 |
| 衣橱、玩法或额度详情已打开，鼠标移出 | 保持显示 | 隐藏且不可点击 | 面板保持可用 |
| 关闭面板并移出，且没有键盘可见焦点 | 隐藏 | 隐藏 | 正在进行的动作仍可结束 |

实现要求：

- 以整个桌宠容器作为 hover 边界，使鼠标能从主体移到工具栏。不得只悬停某个小按钮才显示工具，也不得因经过内部间隙而闪烁。
- 隐藏同时设置 `opacity: 0`、`visibility: hidden`、`pointer-events: none`，避免透明按钮拦截点击或进入 Tab 顺序；显示时恢复三者。
- 当前常规操作区淡入淡出为 0.2 秒，不通过插入 / 移除布局使宠物跳动。轻柔模式应减少过渡。
- 键盘显隐采用 `:has(:focus-visible)`；不能仅以 `:focus-within` 长期保留鼠标点击后的操作区。
- 面板打开状态必须加入显隐判断。面板关闭后重新按 hover / 键盘焦点判断，不能留下强制显示状态。
- 互动提示出现或面板打开时，缩放手柄让位，避免遮住操作与误触缩放。

参考：[鱼缸窗口样式](../src/window.css)、[牛马样式](../src/buddy.css)。

## 3. 点击、拖窗与缩放

### 3.1 输入优先级

按以下顺序处理同一次输入：

1. 按钮、输入框、链接、面板和动作提示处理自身操作，不触发拖窗。
2. 当前玩法需要占用拖动等手势时，在其有效交互区域内优先处理玩法，不移动窗口；例如擦鱼缸或角色专属的擦汗互动。没有此类玩法时不设该模式。
3. 显示的角落手柄用于缩放。
4. 主体上的左键按下，先保留为轻点候选；移动距离达到 5 px 才进入拖窗。
5. 未达到拖动阈值的轻点可触发宠物或道具互动。

必须复用 [useWindowGestures](../src/windowGestures.ts)，保持捕获阶段的拖动判断和拖动后点击抑制。当前拖动结束后抑制 400 ms 内随后产生的点击；不可出现移动桌宠后顺便喂食、摸摸或开宝箱的情况。新增主体命中区应接入现有 `.scene-hit` 约定；若增加新的交互容器，需要同步检查公共手势的排除范围。

手势使用指针捕获，释放、取消、窗口失焦和组件卸载时结束。场景自己的玩法手势状态、延迟单击、动画和定时器也必须清理，不能切换桌宠后继续响应。当前共享手势通过 `.is-wiping` 排除擦拭区域；这是现有实现约定，不意味着新桌宠必须有“清洁”。其他占用手势的玩法也应接入公共手势排除判断。

### 3.2 窗口大小与位置

- 原生窗口保持 1:1；角色在窗口内自行布局，不拉伸角色比例。
- 支持四角拖动缩放、Ctrl / ⌘ + 滚轮缩放、设置中的大小滑杆与预设。
- 当前预设宽度：标准 440 px、紧凑 300 px、迷你 190 px。可设置范围为 180–800 px，并受屏幕工作区限制；工作区比最小尺寸更小时优先保证窗口可见。
- 滚轮每次按当前宽度约放大 6% 或缩小 6%；普通滚轮不改变桌宠大小。手柄聚焦后，上 / 下方向键每次调整 10 px。
- 大小与位置保存到本机；移动和缩放须约束在屏幕工作区内，跨屏操作使用公共主进程逻辑。
- 小尺寸可以缩减文案、隐藏侧栏，但必须保留设置、收起、玩法等基础入口。面板内容超出时可滚动，关闭与结束按钮必须可达。

参考：[窗口几何](../src/shared/windowGeometry.ts)、[Electron 主进程](../electron/main.ts)。浏览器预览不执行真实 OS 拖窗与缩放。

## 4. 互动与面板

### 4.1 每只桌宠独立设计玩法

不规定所有桌宠都要有“清洁”“喂食”“喝水”等固定动作，也不要求动作数量或按钮位置一一对应。先根据角色设定选择有意义的互动，再决定触发方式、道具、反馈和结束条件；不能只替换同一套清洁动画的名称。

| 角色 | 互动示例 | 设计边界 |
| --- | --- | --- |
| 鱼缸 | 清洁玻璃、喂鱼、开宝箱、躲猫猫 | 清洁玻璃可采用海绵拖擦和区域覆盖进度，这是鱼缸的具体玩法 |
| 牛马 | 可设计擦汗、递水、摸头等 | 擦汗只是角色玩法的可选方向，毛巾、汗滴、响应部位与完成方式需独立设计；本文不表示客户端已实现擦汗 |
| 海狸鼠 | 梳毛、喂面、喝水、送木头、收集树叶等 | 梳毛采用有效移动距离；详细动作与边界见 [角色方案](woodland-beaver.md) |
| 后续桌宠 | 根据角色设计，例如梳毛、浇水或整理装备 | 可以使用点击、拖动、长按等不同手势，也可以没有擦拭类动作 |

名称、提示、图标、道具和动画必须与实际互动一致。进度条、区域覆盖、自动完成入口均按玩法需要选择，不是所有桌宠的必备能力。

### 4.2 所有玩法遵循的操作规则

- 主体轻点给出短暂、可见的反馈；角色专属交互可以不同，例如鱼缸点击小鱼、宝箱、洞穴，牛马单击摸摸、双击切换姿态。
- 双击是可选的角色能力，必须处理与单击的冲突。牛马当前将鼠标单击延迟 240 ms，双击时取消该单击。
- 常用动作通过悬停工具栏进入；更多动作通过顶部玩法按钮和右键场景进入。不能把右键或双击作为基础功能的唯一入口。
- 一次只运行一个主要玩法状态；新主要玩法替换旧玩法，清掉旧进度和临时道具。爱心等短暂装饰反馈可叠加，不能阻塞玩法结束。
- 短动作自动回到日常状态；等待用户参与的玩法要提供明确退出方式。持续姿态可以保留，但必须有恢复入口。
- 当前动作提示应说明正在做什么；需要用户操作时说明该玩法的实际手势。需要累计完成的玩法提供可理解的进展反馈，不强制采用百分比进度条。
- 完成条件由玩法定义，并与用户实际操作一致。例如鱼缸清洁按擦过区域去重计数，重复擦同点不能冒充整面完成；该覆盖算法不强制用于牛马擦汗或其他互动。若提供自动执行入口，其完成结果应符合相同玩法规则。
- 衣橱、更多玩法、额度详情必须能主动关闭，打开后不会因鼠标移出而消失。新增桌宠的这些面板应互斥，避免在小窗口中重叠。
- 新增桌宠必须在其容器范围处理 Esc，使当前玩法可取消、当前面板可关闭；不依赖焦点恰好停留在内部画布。鼠标关闭入口仍需保留。

参考：[鱼缸场景](../src/components/Aquarium.vue)、[鱼缸玩法状态](../src/aquarium/play.ts)、[牛马场景](../src/components/BuddyScene.vue)、[牛马玩法状态](../src/buddy/play.ts)。这些实现用于参考公共操作处理，不是新桌宠必须复制的动作模板；具体动作、时长、道具和完成算法由角色方案定义。

## 5. 额度与角色状态

- 所有桌宠共用账户、额度、刷新和错误状态，只改变展示方式。不得为每只桌宠另建登录、查询或余额逻辑。
- 共享账户层提供“使用咚咚账户”和“手动登录其他账户”，设置与托盘均可切换。当前 Tauri 版本首次使用默认选中咚咚，并在启动后自动尝试连接，无需用户再点击登录；前端初始状态和浏览器预览也默认选中咚咚。已有手动账户升级后保持手动模式；后续启动尊重保存的登录方式。
- 手动模式不跟随咚咚切号，也不在登录过期后自动改用咚咚。主动退出账户后暂停自动连接，重启仍保持退出，直到用户明确选择登录方式。
- 自动模式发现咚咚退出或切号时清除旧账户与额度；切换方式、切号和退出均须使旧请求失效，不能让晚返回的结果覆盖新账户。读取不到会话时说明原因并保留手动入口；拒绝的会话等待重新登录咚咚或用户主动重试，临时网络错误使用退避重试。
- 咚咚配置和安装包仅用于本机读取，不改写。原始咚咚会话、临时票据和解密配置不得发给渲染层或写入日志；平台凭据复用系统凭据存储。自动登录以保存会话的有效性为依据，不以进程是否打开作为唯一条件。
- 所有角色互动与换装均为本机视觉效果，不消耗、不增加、不重置真实 API 额度。无论玩法是清洁、擦汗、喂食还是手动充气，文案均不得使人误以为互动能恢复额度。
- 额度数字与金额来自共享数据；单位为人民币 ¥。显示未知状态时使用 `—` 和相应状态说明，不伪造 0% 或 100%。没有额度时可以保留中性角色外观，但不能把装饰水位或形态解释成真实余额。
- `ready` 显示已同步；`stale` 可保留上次额度，但明确“数据待更新”。未登录、连接中、登录过期、跨日同步、不可用和无权限须保留不同语义，不统一伪装成空额度或正常状态。
- 跨日以北京时间和服务端费用日期判断。不得到本地零点就将角色额度设置为满额。
- 临时动作可改变姿态，结束后依据真实额度和仍有效的持续姿态恢复，不把动作帧写回额度状态。

| 桌宠 | 当前额度映射 | 保持的语义 |
| --- | --- | --- |
| 鱼缸 | >60% 充足；>30% 正常；>15% 告警；≤15% 危险 | 水位随额度变化；各档保持蓝色水体，不用红 / 黄水替代额度状态 |
| 牛马 | >60% 饱满；>25% 略瘪；>15% 明显瘪；≤15% 瘫软 | 以饱满程度与日常姿态表达额度；木牌数字仍是额度依据 |

所有桌宠的最后一个额度形态统一在剩余 ≤15%（包含 15% 与 0%）时触发，恢复到 >15% 后按当前额度分档。末档仅表示视觉休息 / 极低额度，不能把仍有余额写成“额度耗尽”；真实耗尽、金额和提醒阈值保持各自规则。未知值不得进入末档。其他分档按角色定义；原来以 10% 为倒数第二档上界的角色统一提高到 20%，保留 15%～20% 的低额形态。必须覆盖满额、中间、低额、15% 边界、零额与未知状态，并写清映射。

参考：[共享状态契约](../src/shared/types.ts)、[额度规则](../src/shared/quota.ts)、[应用状态映射](../src/App.vue)。

## 6. 设置、场景切换与托盘

- 公共偏好共用：置顶、鼠标穿透、开机启动、窗口尺寸、昼夜、轻柔模式和通知；每只宠物独立保存皮肤 / 装扮。
- 切换桌宠不改变账户、额度、窗口大小位置或公共偏好，也不覆盖其他桌宠的装扮选择。
- 桌面端通过设置和托盘切换场景，浏览器预览通过顶栏切换。新增桌宠必须接入这三处入口。
- 设置经 `api.settings()` 和共享校验持久化，场景组件不直接写原生文件。新增字段需要默认值、合法值校验和旧设置兼容。
- 桌面设置打开独立设置窗口；浏览器使用预览设置面板。不得把完整设置页挤进桌宠主体。
- 收起按钮和关闭悬浮窗口都进入托盘，不退出进程；退出使用托盘的明确退出操作。
- 鼠标穿透是用户显式开启的窗口级偏好，不等同于隐藏工具栏，也不等同于透明像素自动穿透。穿透开启后，必须能从托盘关闭穿透、显示桌宠或打开设置。

参考：[设置校验](../src/shared/settings.ts)、[界面桥接](../src/bridge.ts)、[场景选择器](../src/components/ScenePicker.vue)、[设置面板](../src/components/SettingsPanel.vue)、[Electron 主进程](../electron/main.ts)。

## 7. 动效与可操作性

- 支持白天、夜晚、自动昼夜；当前自动模式按本地时间 19:00–次日 07:00 为夜间。主题只改变视觉，不改变额度和交互含义。
- 轻柔模式减少持续游动、摇晃、粒子和过渡，仍保留动作结果、必要的进展反馈和操作入口。
- 宠物主体、道具、状态文字、按钮分层；真实数值由界面渲染，不能把整张设计图当作可交互界面。
- 装饰层不拦截指针。角色或道具的可点击范围随当前布局和尺寸变化，不能明显偏离视觉对象。
- 基础入口使用可聚焦的语义按钮，图标按钮有可读名称；键盘 Enter / Space 可操作，焦点可见。画布中的互动对象提供对应命中控件。
- 页面隐藏时减少无效动画工作，卸载后停止动画与监听；素材加载失败要有可理解的提示，不能只留下空白。

## 8. 新增桌宠的实施与验收清单

先写角色专属方案：常态外观、额度分档、未知态、主体点击、可选双击、常用 / 更多动作、皮肤与昼夜素材。每个动作注明名称与含义、入口、手势及有效区域、道具与反馈、完成条件、取消 / 重入规则，以及是否需要进度或自动执行。公共操作规则直接引用本文，不从旧桌宠复制固定动作清单。

接入时检查 `Scene` 类型、默认值与设置校验、App 场景分支与标题、ScenePicker、设置内装扮入口、托盘场景菜单与名称，以及公共手势对新增交互区域的识别。沿用共享桥接和主进程，不复制公共服务。

每只新增桌宠必须记录以下结果；可选能力按角色方案验收，未设计的双击、擦拭、进度或自动执行等标记“不适用”，不为勾选清单强加玩法：

- [ ] 初始无悬停时常规操作全部隐藏，核心主体和额度可见。
- [ ] 移入显示；主体移到工具不闪烁；移出隐藏；点击再移出不因残留焦点常驻。
- [ ] 键盘进入主体后操作区显示，能继续进入工具；离开后按显隐规则收起。
- [ ] 面板移出不消失；关闭、Esc、重入和面板切换可用；面板 / 动作提示期间缩放手柄隐藏。
- [ ] 主体轻点与拖窗互不误触；拖动后不触发点击；如有双击，不额外触发单击动作。
- [ ] 角色动作名称、道具、提示、动画与设定一致，没有为套模板强加“清洁”等无关动作。
- [ ] 如有占用拖动等手势的玩法，在有效区域内不误触拖窗；退出后恢复公共窗口手势。
- [ ] 每个动作按自身规则完成，进展反馈与实际操作一致；如有自动执行，其结果与该玩法规则一致；结束和切换新动作可用。
- [ ] 四角、修饰键滚轮、设置滑杆和预设缩放正常；小尺寸与屏幕边界可用，重启恢复位置大小。
- [ ] 每个玩法有反馈、结束 / 恢复路径；连续切换与切换桌宠后无遗留道具、定时器或捕获。
- [ ] 满额、中间、低额、零额、未知、过期与跨日状态正确；所有互动前后额度不变。

## 9. 当前实现差异与历史边界

以下是本次源码核对发现的差异，后续新增桌宠不得照搬；本次只整理文档，不修改这些运行逻辑。

- **Esc 尚非容器级统一行为**：鱼缸 App 层 Esc 只关闭玩法 / 衣橱，额度详情不随其关闭；玩法取消依赖 Aquarium 内的键盘事件。牛马容器 Esc 关闭面板，玩法取消依赖 BuddyScene 内的键盘事件。不能宣称从任意焦点按 Esc 都能结束全部互动。
- **面板互斥尚不彻底**：鱼缸详情与玩法面板独立，牛马状态按钮也未在所有路径关闭更多动作面板。第 4 节规定的是新增桌宠应采用的一致行为。
- **现有牛马仍使用清洁玩法**：鱼缸再次点清洁会取消；牛马当前再次点清洁会重置进度。本文将清洁归为角色专属玩法，擦汗是牛马可采用的设计方向，本次未修改客户端名称、素材或玩法逻辑。新角色应独立定义动作与重入规则，并保留明确结束入口。
- **入口能力不同**：鱼缸玩法菜单已有截图，牛马尚无对应菜单项。截图不是两只桌宠都已具备的基础入口；需要接入时复用公共截图 API。
- **牛马旧方案不是当前外观依据**：[充气牛马计划](charging-buddy-plan.md) 中的完整草地背景和估计动作时长属于历史设计。当前桌面采用透明背景、局部草地和角色物件，动作时长以当前状态机为准。
- 本文没有新增跨平台验收结论。此前本地浏览器已检查牛马常规操作的隐藏、悬停、面板保持、点击后移出与键盘显隐，类型检查通过；这不证明两只桌宠已完成本文所有原生检查项。
