## 共享行为

`state.ts`、`controller.ts` 继续接共享 `quotaDisplay`，统一处理来源切换、有效账户、过期数据、系统减少动态效果、窗口隐藏和互动占用。主动切换来源、角色或当前皮肤 / 形态播放变身；来源切入 1.6 秒、退出 0.6 秒、觉醒换装 1.6 秒（原生形态换装 0.8 秒），轻柔模式 0.2 秒。启动恢复、刷新和后台重连直接显示对应形态。新服装提前加载，冷加载就绪后再开始；衣橱等面板关闭后播放最后一次选择。主体过渡统一作用于图像 / 画布，保留角色自身动作变换，不影响数值与操作命中区。关闭动效仍保留新造型。

各 Experience 使用原来的窗口手势、玩法状态机、额度、消息与日程服务；没有增加单角色账户服务或修改真实额度。加载失败显示原造型和重试入口，不能把素材错误当作账户错误。

## 素材与渲染

- 图集并非严格均分：按列寻找行间隔并逐格标定主体透明边界。运行时清除裁切边缘的微小孤立残片，防止邻格的头饰 / 脚部混入。每套服装共用缩放比例和地面基线，躺姿不会被放大到站姿高度。
- `useAwakenedArt` 处理快速换装与卸载竞态。错误请求会从缓存移除；已解码衣橱缓存最多保留 12 套。不认识的皮肤不会借用其他皮肤。
- 土豆、食人花、狐狸替换角色本体，外部道具和反馈沿用原入口。月汐复用现有形变与武器系统，修仙将六帧打包成原 WebGL 所需布局。
- Canvas 角色在身体绘制处分支选择新整身图，不绘制原来的裸身体 / 多余手脚；消息、工具、轮子、树和背景分别绘制。小恐龙与肥嘟嘟的奶茶、饼干、软垫、毯子及电脑使用独立道具图。修复肥嘟嘟待机与喝茶共用同一帧时不重绘道具的问题。
- 电池实时百分比仍由代码绘制，卧倒图不再额外旋转 90 度。鱼缸保留原来的游动、水位与玩法，换装选择改为对应的完整新鱼。

## 后续动作精调与验收边界

这是素材齐备后的首轮接入，不是全部动画的最终验收。新整身图目前使用整体呼吸、位移和有限形变；牛马、海狸、招财猫、电池的独立关节动作、仓鼠连续奔跑步态、狐狸细部表情与肥嘟嘟眼耳动作仍需按新服装重标关节。月汐武器握点沿用原衣橱坐标，需逐套校准。已有玩法入口、完成条件与道具反馈保留，但不能据此声称新造型的所有动作接触点都已验收。

未穷举每套皮肤 × 每个玩法 × 消息组合。macOS / Windows 原生透明窗口、拖窗、托盘、穿透、休眠恢复和真实账户本轮未验证；本轮没有发布、提交或推送版本。
