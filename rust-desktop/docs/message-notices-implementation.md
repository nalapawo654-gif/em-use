# 咚咚消息提醒 · 实现说明

2026-09-14。v0.4.4 后的位置和弹窗修正，当前修正尚未发布新版本。

## 账户规则

| 变化 | 额度 | 消息 |
| --- | --- | --- |
| 手动 / 扫码登录 B，本机咚咚是 A | B | A |
| 切换或退出额度账户 | 按额度操作变化 | A 的监听和提醒保留 |
| 本机咚咚 A 换成 C | 手动 B 不变；跟随模式按原额度逻辑更新 | 清除 A 的旧卡片和角标，建立 C 的新基线 |
| 咚咚退出登录或退出运行 | 手动额度不受影响 | 清理旧提醒，显示等待连接 |

设置中分别显示两个账户；消息页提供当前咚咚姓名与账户标识。两者不一致不会报错，也不会自动替用户切换额度。

## 当前交互

- 11 只桌宠各有专属道具：水泡信、邮包、树叶信、齿轮信、纸鹤、通信屏、奶茶便笺、水墨信、金铃、手机、月牙信。原角色、服装和额度素材保留；其中肥嘟嘟、仓鼠、海狸鼠、小恐龙已将消息物料接入角色绘制层，按持物、原杯挂信、膝上及累倒落地切换。
- 新消息气泡使用桌宠外侧的独立窗口，不抢输入焦点；约 5 秒后收起，鼠标移入暂停计时。迷你桌宠也使用可读宽度的气泡。点击 `×` 或自动收起不减角标。
- 道具按参考图分别靠近角色身侧、手边或脚边；迷你尺寸独立校准，不能遮挡台词、额度和悬停操作栏。
- 点击道具或气泡打开桌宠旁的独立卡片；屏幕边缘换侧放置。`×`、收起、Esc 或切换到其他窗口关闭；不改变桌宠尺寸。
- 多会话按会话标识分组，实际进入并看到某条提醒时才减少本工具角标；会话列表本身不把内容算作已查看。新会话不会打断当前阅读。只保留当前会话期间最近 100 条提醒，重启不恢复提醒历史。
- 支持隐藏姓名 / 正文、暂停 30 分钟 / 1 小时、恢复提醒、遵循咚咚免打扰。隐藏正文在原生 IPC 发出前完成；暂停不补弹。图片、语音、视频和文件仅用文字摘要表示。
- 打开咚咚优先选择当前运行的安装路径，Windows 直接启动客户端触发单实例唤起，macOS 通过 Launch Services 激活应用。按钮显示处理中状态，失败保留具体原因并允许重试。列表按钮只唤起客户端，详情按钮使用 `emdongdong://chat/start` 定位当前私聊 / 群聊，原生侧按当前账户的 opaque conversation key 查询真实 ID 并复查来源；不回复。仅显式点击才跳转，客户端自身的已读行为按咚咚规则。正在玩法、拖动、衣橱、额度详情或版本更新中时暂缓提示；切换桌宠不重播旧提醒。

## 原生接收

`src-tauri/src/message_source.rs` 只读打开当前咚咚加密消息库；从本机安装包取得匹配的 WASM 模块，在限制内存和运算量的解释器中使用。SQLite 只读连接并开启 `query_only`，不写入消息、附件或登录配置，不需要 Node 常驻进程。

每秒检查进程、配置摘要和数据库版本；配置不变时复用已解析会话，数据库未变时不查询消息，失败间隔 5 秒重试。初次连接、换号和断线重连建立新基线，不把已有历史消息作为新提醒。每批最多读 200 行并继续取后续批次；过滤自己发送、过旧、已读、撤回、隐藏和免打扰记录。

`messages.rs` 独立维护来源代次、去重和提醒队列；不访问额度 token、登录模式或额度请求代次。换号会更换代次，拒绝旧界面提交的查看记录；查询完成后再次核对配置，丢弃切换期间的结果。密钥、原始消息 ID 和会话凭据不传给界面，不记录消息正文日志。

### Windows 消息卡片焦点修正（2026-09-14，v0.4.6）

- 用户反馈 Windows 点击海狸鼠消息道具打不开卡片。源码存在风险：原先收到 `Focused(false)` 就立即销毁消息窗口；当前 Tauri Windows 实现会将 WebView2 的 `LostFocus` 转成该事件。未在用户机器取得事件日志，因此这是源码定位出的可疑原因，不能视为已真机复现。
- 卡片创建时不抢先激活，设置位置、显示后再激活。失焦关闭只在首次获得焦点后启用，延迟 200 ms 再核实；重新聚焦和销毁均使旧检查失效。Windows 使用 [GetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getforegroundwindow) 对比整个窗口，避免把 WebView2 内部焦点转移误判为切换窗口。其他平台保留窗口焦点查询。`×`、收起、Esc 仍直接关闭。
- 消息道具正在打开时忽略重复点击；道具和气泡均保留原生错误的阶段与原因，允许重试。
- **源码 / 测试：**macOS 上 Rust 30 项通过，2 项真实账户测试未运行；包含首次激活前失焦、内部焦点转移、重新聚焦和销毁后的旧检查四项回归。契约、类型检查、前端构建通过。
- **浏览器：**`scripts/message-window-regression-qa.py` 使用海狸鼠演示数据，验证点击开卡、重复点击合并、错误提示、失败重试、收起后重开、键盘进入及 Esc 关闭、打开咚咚桥接调用和气泡错误提示；无页面脚本错误。运行前启动 `npm run dev -- --port 5188`，再运行 `python3 scripts/message-window-regression-qa.py`（需要 Python Playwright 及 Chromium）。
- **未验证：**本轮 macOS 原生交互、Windows 目标编译和真机焦点事件、真实消息到卡片端到端链路。本次修正纳入 v0.4.6，安装包构建结果以该标签的 GitHub Actions 为准。

### 连续消息气泡合并（2026-09-16）

- 气泡按会话选择，连续来信原地更新最新正文与新提醒条数，不因每条消息调用原生显示入口；原始消息移出 100 条保留列表后，气泡仍跟随同一会话。
- 手动收起或 5 秒超时后，同一会话继续来信只更新角标；距离该会话上一次来信满 30 秒后才重新弹出。已全部查看、消息账户切换会重置抑制。不同会话独立，不按显示姓名混合；气泡被抑制不代表已读。
- 源码 / 测试：157 项 TypeScript 测试、8 项发布脚本测试、35 项 Rust 测试通过，3 项真实账户测试仍忽略；类型检查、Vite 构建与基线检查通过。
- 浏览器：`scripts/message-burst-qa.cjs` 验证连续 4 条消息仅一次显示调用、同一气泡 DOM、最新内容与条数、原始消息移除、手动关闭后静默、超时后静默、其他会话可提示及未读保留。
- 未验证：真实咚咚连续来信的原生端到端过程、Windows 真机。尚未打包或发布，现有已安装版本不会自动获得源码修正。

### 指定私聊自动回复试用版（2026-09-20，未发布）

- 设置 → 咚咚消息新增自动回复配置。默认关闭，从本机私聊或咚咚通讯录搜索中选择最多 20 位联系人，填写固定文案后明确开启一小时；配置仅在当前进程保留。
- `auto_reply.rs` 在原生层管理白名单、5 秒安静窗口、每人 30 分钟冷却、待发送取消与最近 20 条回执。任何群聊、群内 @、未知类型、旧消息、自发 / 非文本 / 已读 / 撤回 / 免打扰消息均不触发。本人手动回复后暂停对应联系人，收到本次自动回复回声不形成循环。
- `message_source.rs` 的读取连接仍然只读。来信必须同时满足 message.chat_type=1、chat.type=1、group_id 为空、chat.badge_id 与对方一致、owner_id 为本人、收发双方匹配。实际发送前重新查询确认消息仍有效、会话未改变、本人没有后续发言；前端只能传会话代次和原生生成的联系人 key，不能传实际群目标。
- 发送通道根据本机咚咚 3.4.1 安装包中的客户端实现接入，固定 POST `/chatserver/app/api/message/send/`、chatType=1、toGroupId=null。凭据只在原生 HTTP 层使用，无数据库写入。只有匹配收件人的有效私聊消息回执才显示已确认发送；超时、失败或回执不确定均关闭自动回复，不自动重试。已交给服务器的请求不能因点击关闭而撤回。
- 断开 / 切换咚咚、读取失败、关闭 / 暂停消息提醒、到期或重启后关闭。额度账户切换不改变消息来源。消息清除、角色动画、拖窗和现有消息气泡逻辑保持原有路径。
- **源码 / 测试：**44 项 Rust 测试通过，3 项真实账户测试默认忽略；157 项 TypeScript、8 项脚本测试，以及类型检查、构建和素材 / 交互一致性检查通过。新增覆盖双重私聊判定、无群名群聊、群内 @、未知身份、手动回复、连续消息、关闭 / 编辑 / 到期 / 切号取消、冷却与失败不重试。
- **浏览器：**`scripts/auto-reply-qa.cjs` 已验证默认关闭、联系人 / 文案提交、开启后锁定编辑、关闭、失败反馈和切号清空选择；960 px 与 640 px 视口检查，截图为演示账户。没有调用真实发送接口。
- **本机真实账户只读：**咚咚消息库打开、私聊联系人查询和基线读取通过。**真实发送回执、双方聊天同步、macOS 原生交互及 Windows 真机未验证**，不能用浏览器模拟或测试通过代替。


### 咚咚通讯录搜索（2026-09-20，未发布）

- 原搜索仅过滤本机最多 100 个私聊会话，无法找到不在列表中的同事。新增人员查询，沿用咚咚 3.4.1 的 `POST /chatserver/app/api/search/?searchType=CONTACT_V2`，载荷为 content、type=CONTACT_V2、params.pageNum/pageSize。只接受人员结果，账号 / 名称 / 部门清理后返回；群结果、本人、缺失账号与重复账号排除。

### 自动回复在本机咚咚不可见：排查与恢复（2026-09-20）

- 用户确认收件方能收到自动回复，但发送方咚咚会话未显示。核对已安装的咚咚 3.4.1：正常发送先调用 `saveMessageLocallyAndRefresh` 写入临时消息，再发送 HTTP 请求，收到回执后替换本地消息并刷新视图。桌宠仅调用发送 API，不经过这段客户端流程；服务端发送回执不能作为本机显示成功的证据。
- **原生真实账户恢复已验证：**咚咚头像菜单 → 设置 → 通用 → 恢复聊天记录，选择当天的起止日期并确定。同步完成后打开原私聊，先前缺失的「自动回复」出现在右侧并显示已读。此次只恢复已有记录，没有发送或重发消息，也没有由桌宠写入咚咚数据库。
- **自动同步仍未解决：**安装包中存在内部历史同步函数，但已检查的外部协议入口不提供调用它们的能力。`msgRefresh` 用于投票、日程等特定卡片更新，不能作为补入普通文本消息的接口。未据此修改发送参数、冒用其他终端类型或添加重试；当前程序发送成功后仍可能需要用户在咚咚恢复当天记录。
- 本次只记录诊断和恢复结果，未修改自动回复实现。上述原生恢复结果不代表后续自动同步、Windows 客户端或新版安装包通过验收。

### 桌宠内阅读正文、图片与真实回执（2026-09-20，未发布）

- **零新提醒的物料修复：**公共消息道具过去由历史提醒是否存在控制，导致全部阅读后仍显示。现改为 `newCount > 0`；保留历史或仅处于暂停状态不会展示消息物料。读完后清除对应气泡并恢复角色正常绘制，不关闭已打开的阅读卡，历史继续通过设置入口查看。此规则复用于所有桌宠，不影响普通奶茶等互动道具。

#### 本地读取性能修复

- 聊天正文始终共用咚咚的本地数据库，以只读连接访问；桌宠不另建聊天数据库、不写入咚咚记录或索引。已展开正文和图片只作进程内缓存，不保存到桌宠数据目录，退出释放。
- 原历史查询对没有引用的消息也执行引用子查询；本机实测一页 30 条耗时 2521–2943 ms。改为先限定当前页，再关联发送人、附件和真实存在的引用；同一测试私聊改后为 73–113 ms。最近会话改用咚咚维护的最后消息标识，只查询最近 50 个会话，从 5779 ms 降至 37 ms。
- 正文、图片、已读确认共用阅读服务持有的只读连接；会话解析仅在本机配置变化时重做。缓存连接每次检查来源、数据库路径及文件身份，换号、数据库替换、关闭正文预览或停用提醒时失效。查询不持有跨请求事务，复用连接仍读取最新提交。
- 54 项 Rust 测试通过，新增分页边界、引用撤回、复用连接读取新提交、历史补入不覆盖最后会话消息、隐藏会话和只读保护回归。性能数字来自真实本机数据库的只读查询计时，不等于包含图片网络下载和界面绘制的总耗时；本次未发送消息或提交已读。

- 最近会话从本机只读库加载 50 个会话，历史每页 30 条、最多 500 条。新提醒仍以连接后的新消息为基线，历史不会冒充提醒。已读消息保留在阅读记录中；清除提醒不删除历史。
- 普通文本保留全文；富文本提取文字与图片并保留顺序，引用提供摘要。图片优先读取当前账户下的本地缓存，缺失时由原生层访问咚咚图片服务，支持普通图片及富文本媒体两种鉴权路径。图片格式限 PNG/JPEG/GIF/WebP，单张上限 16 MiB，界面并发上限 2、图片缓存约 48 MiB；路径、媒体标识和凭据不传给渲染层。
- 正文逐段至少 80% 可见并停留 1.2 秒，图片成功加载后才计入阅读完成；必须前台聚焦。不完整内容、未展示部分、图片加载失败和后台窗口不自动提交回执。正文预览关闭 / 切号清空内容并废弃旧响应。
- 完整阅读通过咚咚 `message/v3/batchRead` 提交真实消息 ID，只接受 HTTP 成功且业务成功的回执。阅读取消对应消息尚未发送的自动回复。清除提醒仍是本地操作，不代表已读。
- **原生 / 真实账户：**用户指定私聊的新图文在 macOS 原生桌宠内完整显示，图片可见；通过桌宠阅读后显示「服务端已读 · 本机待同步」。只读诊断也确认本机已读尚未更新。此前已分别验证本地缓存图片、普通远程图片、富文本远程图片可用。未向联系人发送测试消息。
